## 第一次：scheduleBatch

在 BNB Smart Chain 上选中 Safe `0x1f502a0b76EA9b42821B82e424C741AeF87C3D03`，进入 **New Transaction → Transaction Builder**。输入本次 Timelock 地址，粘贴 ABI，选择 `scheduleBatch`。

| 界面字段 | 手工填写内容 |
| --- | --- |
| Contract address / To | `0x02f453192530e07541E61B43DA079273F410979b` |
| Native value / BNB amount | `0` |
| targets (`address[]`) | 完整复制 [targets.txt](./targets.txt)，四项均为本次 Factory 代理地址 |
| values (`uint256[]`) | 完整复制 [values.txt](./values.txt)，即 `["0","0","0","0"]` |
| payloads (`bytes[]`) | 完整复制 [payloads.txt](./payloads.txt)，保留每项 `0x` 前缀和全部字符 |
| predecessor (`bytes32`) | 完整复制 [predecessor.txt](./predecessor.txt)，为 32 字节全零 |
| salt (`bytes32`) | 完整复制 [salt.txt](./salt.txt)，不要改写或随机生成 |
| delay (`uint256`) | `600`，单位为秒 |

数组应包含方括号、英文逗号及双引号；不要将整个数组再包成一个字符串。四个 payload 按顺序调用 `approveTemplate`、`approveConfig`、`selectConfiguration`、`resumeCreation`，不要拆分或调整顺序。

加入交易后，核对链 56、目标 Timelock、value=0、方法与字段。两位 Safe owner 都确认，然后实际执行上链。达到 2/2 签名但尚未执行时，10 分钟计时还没有开始。

`operationId` 是根据 targets、values、payloads、predecessor、salt 计算出的结果，不是 scheduleBatch 或 executeBatch 的输入参数。无需在界面寻找 operationId 输入框。

## 第二次：executeBatch

schedule 实际执行上链后，运行：

```bash

  --deployment live-test/deployment-state.json --inspect
```

如果采用导入方式，第二笔用 [safe-execute-1792417534419.json](../observations/safe-execute-1792417534419.json)，同样必须先取得 READY 检查结果。

这是第二笔独立 Safe 交易，需要两位 owner 再次确认并执行，不能重用第一次的签名。执行后再次运行 `--inspect`，应得到 `ALREADY_EXECUTED`。

## 其余三个方法

| 方法 | 用途 |
| --- | --- |
| hashOperationBatch | 只读计算 operationId；输入第一次的前五个字段，不含 delay |
| getTimestamp | 只读查询 operationId 对应时间；0 为未安排，1 为已完成，其余为可执行时间戳 |
| isOperationReady | 只读查询 operationId 是否已经到达执行时间 |

这三个方法用于查询，无需发起 Safe 交易；本地 `--inspect` 已执行相关核验。真实 Safe 双签和外层交易 gas 仍应以主网回执为准。
