## 5. 100 个 ID、45 / 55 份能否各用一笔领取

**可以在 100 份版本中实现：A 提交自己持有的 45 个 ID，B 提交自己的 55 个 ID，各发一笔批量领取交易。** 前端“领取全部”按钮可先获取当前持有 ID，再一次提交。合约逐 ID 校验持有权，分别扣除历史已领金额，最后合并支付。

领取金额 = 所提交各 ID 的“累计应得收益 − 该 ID 历史已领收益”之和。

如果 100 个 ID 各发行 1 份、权重相等，则 A 对新分配收益享有 45%，B 享有 55%。历史未领金额和曾经转移的权益仍须按 ID 计算；不能直接用当前合约余额乘以 45% 或 55%。

只领已进入 Vault 的权益可调用 claimBatch(ids)；如果要把矿机新收益一并领取，可使用先 harvest 再批量结算的 harvestAndClaim(ids)。上述“一笔”指每个地址各一笔，仍需传入它希望领取的完整 ID 列表；仅持有多个 NFT 不会让单 ID 调用自动领取其余 ID。

**当前部署版本仅支持 #1、#2，批量列表最多 2 项，分配分母固定为 2。** 100 份版本需要修改这些限制、实现完整去重与逐 ID 权限校验，并用 45 / 55 项真实规模测试 gas、模拟和目标链执行限制。本次两份额主网赎回并未证明 100 份版本已经实现或能在一笔交易的 gas 限制内完成。

代码依据：src/TestMinerVault.sol 第 155–156 行（分配）、174–199 行（批量领取）、210–229 行（赎回）及 304–305 行（ID 限制）。ERC-1155 定义转账、余额与事件接口，收益领取逻辑来自本项目合约；持有 ID 列表可通过已知 ID 查询或事件索引取得。参见 [ERC-1155 标准](https://eips.ethereum.org/EIPS/eip-1155#enumerating-from-events)。
